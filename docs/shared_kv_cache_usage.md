# Shared KV Cache Reuse: Usage Notes

This document explains the current DualMap behavior for KV reuse in the existing repository architecture.

> Scope note: this is **not** a distributed RPC/IPC transport design. It documents the current shared-pool semantics used by DualMap.

## What is implemented

When `enable_shared_kv_pool=True`, replicas use a shared KV namespace and classify prefix tokens into three categories:

1. **local reuse tokens**
   - KV blocks already located on the selected replica.
   - Accounted with `local_hit_tprt` in TTFT estimation.

2. **cross-instance reuse tokens**
   - KV blocks generated by a different replica but reusable via the shared pool.
   - Accounted with `remote_hit_tprt` (or `tprt` fallback) in TTFT estimation.

3. **miss tokens**
   - KV blocks not found in shared pool.
   - Accounted with `tpct` (prefill/recompute token cost).

## TTFT cost decomposition

Conceptually:

```text
estimated_ttft ≈
    miss_tokens * tpct
  + local_reuse_tokens * local_hit_tprt
  + cross_instance_reuse_tokens * remote_hit_tprt
  + waiting terms (same decomposition)
```

## Execution-side token accounting

In request admission accounting:

- `actual_num_prefill_tokens` tracks only **miss tokens**.
- Reusable tokens (local/cross-instance) are excluded from full recompute token count.

## Main config knobs

- `enable_shared_kv_pool`
  - `True`: enable shared-pool reuse classification and accounting.
  - `False`: preserve legacy per-replica local cache behavior.
- `tpct`: miss/recompute token time.
- `local_hit_tprt`: local reuse token time.
- `remote_hit_tprt`: cross-instance reuse token time.
  - If omitted, scheduler uses `tprt` as fallback.
- CLI mapping in `start_up.py`:
  - `--local_hit_tprt`
  - `--remote_hit_tprt` (optional; defaults to `--tprt`).
  - `--force_output_len_1` (optional; force each request output length to 1).

## Compatibility behavior

With `enable_shared_kv_pool=False`:

- behavior falls back to local-only cache accounting;
- cross-instance reuse is not applied.

## Quick validation

```bash
PYTHONPATH=. pytest -q tests/test_shared_kv_pool.py
```

The test file includes coverage for:
- cross-instance reuse admission accounting,
- TTFT local-vs-cross cost distinction,
- compatibility fallback when shared pool is disabled.

## 中文使用说明（维护者版）

### 1) 何时开启共享池

- 需要验证“跨实例 KV 复用”时：设置 `enable_shared_kv_pool=True`。
- 需要回退旧逻辑或做对照实验时：设置 `enable_shared_kv_pool=False`。

### 2) 三类 token 的成本

- `local reuse tokens`：当前副本已有 KV，成本系数 `local_hit_tprt`。
- `cross-instance reuse tokens`：其他副本已有但可复用，成本系数 `remote_hit_tprt`（默认回退到 `tprt`）。
- `miss tokens`：共享池不存在，成本系数 `tpct`，并进入 prefill/recompute。

### 3) 执行侧观察点

- 请求进入 admission 后，`actual_num_prefill_tokens` 仅对应 miss tokens。
- 如果共享池命中（local 或 cross-instance），这些 token 不应再计入 full recompute。

### 4) 最小验证命令

```bash
PYTHONPATH=. pytest -q tests/test_shared_kv_pool.py
```

### 5) 集群级 TPS 分析脚本

新增脚本：

```bash
python evaluation/plots/dataset_performance/cluster_tps_analysis.py \
  --csv ./evaluation/result/data/.../request_metrics.csv \
  --ttft_slo 5 \
  --include_per_replica
```

统计口径：

- `cluster_tps`：`sum(output_len) / (max(request_end_time)-min(request_start_time))`
- `mean_request_tps` / `p50_request_tps` / `p95_request_tps`：基于 CSV 的 `TPS(tokens/s)` 请求级分布
- 传 `--ttft_slo` 时额外输出：
  - `ttft_slo_attainment`：`time_to_first_token <= ttft_slo` 的比例
  - `goodput_req_per_s`：`ttft_slo_attainment * num_requests / makespan`
- `--include_per_replica`：同口径按 `replica_id` 分组输出
